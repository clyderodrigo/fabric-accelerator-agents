# Claude Code adapter

Generated by `scripts/build.ps1` from the repository's `shared/` source. Do not edit anything in
this folder — edit `shared/` and rebuild.

This adapter is a **Claude Code plugin**. It ships skills, read-only subagents, slash commands, the
guardrail policy documents and the runbooks. It also bundles the two official Fabric MCP servers,
which is why the generated permission rules use the plugin-scoped tool form.

## What you need first

| Requirement | Why |
| --- | --- |
| Azure CLI, signed in | `az login --allow-no-subscriptions`. The MCP token helper shells out to it. |
| Node.js 22 or later | Runs the token helper and the local Fabric MCP server. |
| A Fabric identity that can see the target workspaces | Every MCP call runs as that identity. |
| A trusted project folder | Not needed for the plugin's own servers, but needed for anything you add to `.mcp.json` yourself. |

## Install

From this repository root:

```powershell
claude plugin marketplace add .
claude plugin install fabric-accelerator@fabric-accelerator
```

Or, without a marketplace, point Claude Code at the plugin directory directly for a single session:

```powershell
claude --plugin-dir ./adapters/claude-code
```

## Apply the guardrails

Permission rules cannot live in a plugin. Copy the generated template into the repository you are
deploying from:

```powershell
New-Item -ItemType Directory -Force .claude | Out-Null
Copy-Item ./adapters/claude-code/settings.template.json .claude/settings.json
```

If you already have a `.claude/settings.json`, merge the `permissions` block by hand rather than
overwriting it. The block has three arrays:

- `deny` — every `delete_*` tool. A deny removes the tool from the model's context, so it cannot be
  attempted at all.
- `ask` — every other mutating tool, including the role-change tools.
- `allow` — the read-only tools and the offline documentation tools.

## Copy the runbooks and the config contract

The skills read `fabric/` from **your** repository, not from the plugin:

```powershell
Copy-Item -Recurse ./adapters/claude-code/fabric ./fabric
Copy-Item ./fabric/declared-environment.example.yaml ./fabric/declared-environment.yaml
```

Then fill in `fabric/declared-environment.yaml`. Its schema is documented in
`fabric/declared-environment.md`.

## Verify the installation

```powershell
claude mcp list
```

You should see two servers:

| Server | Expected state |
| --- | --- |
| `fabric-core` | connected — remote, token minted by the header helper |
| `fabric-local` | connected — stdio, documentation only, no Fabric authentication |

Then in a session:

```text
/mcp
```

Check that the tool names look like `mcp__plugin_fabric-accelerator_fabric-core__list_workspaces`. If
they do not, your plugin name differs from the default and the generated rules will not match. Fix it
by rebuilding with the real name:

```powershell
powershell -NoProfile -File ./scripts/build.ps1 -PluginName <actual-plugin-name>
```

Then copy `settings.template.json` again.

## Try it

```text
/verify-env
/drift-check
/provision-check dateng
```

Or ask directly: *"Verify the [DEV] DatEng workspace against fabric/declared-environment.yaml."*

The `verifier` and `drift-checker` subagents have a `tools:` allowlist of read tools only. They cannot
write, run shell commands, or delete anything, regardless of the project's permission rules.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `fabric-core` fails to connect | No Azure CLI token | `az login --allow-no-subscriptions`, then `/mcp` and reconnect |
| Token helper times out | `az` not on PATH for the shell Claude Code uses | Install Azure CLI, or add it to PATH, then restart Claude Code |
| Every Fabric tool prompts | Plugin name differs from the generated prefix | Rebuild with `-PluginName`, re-copy the settings template |
| `fabric-local` will not start | Node older than 22, or `npx` blocked | Install Node 22 LTS; check `npx -y @microsoft/fabric-mcp@latest --help` |
| A `delete_*` tool is missing from the tool list | Working as designed | The deny rule removed it |

## What this adapter cannot do

It cannot assign a workspace to a capacity, connect Git, create or bind connections, or configure
deployment pipelines. No official Fabric MCP tool exposes those operations. Those steps are in
`fabric/runbooks/` and are performed by a human in the Fabric portal. See the verification honesty
matrix in `AGENTS.md`.
