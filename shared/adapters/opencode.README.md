# OpenCode adapter

Generated by `scripts/build.ps1` from the repository's `shared/` source. Do not edit anything in
this folder — edit `shared/` and rebuild.

This adapter is a **project configuration**, not a plugin. OpenCode loads `opencode.json` plus
`.opencode/agents`, `.opencode/commands` and `.opencode/skills` from the repository you run it in.

## What you need first

| Requirement | Why |
| --- | --- |
| Azure CLI, signed in | `az login --allow-no-subscriptions`. It mints the MCP token. |
| Node.js 22 or later | Runs the local Fabric MCP server. |
| A Fabric identity that can see the target workspaces | Every MCP call runs as that identity. |

## Install

From your deploying repository, copy three things:

```powershell
Copy-Item ./adapters/opencode/opencode.json        ./opencode.json
Copy-Item -Recurse ./adapters/opencode/.opencode   ./.opencode
Copy-Item -Recurse ./adapters/opencode/fabric      ./fabric
Copy-Item ./adapters/opencode/AGENTS.md            ./AGENTS.md
Copy-Item ./fabric/declared-environment.example.yaml ./fabric/declared-environment.yaml
```

If you already have an `opencode.json` or an `AGENTS.md`, merge rather than overwrite: keep the
existing `mcp.servers` entries and append the generated `permissions` array.

Then fill in `fabric/declared-environment.yaml`. Its schema is in `fabric/declared-environment.md`.

## Set the token before launching

OpenCode has no `headersHelper`, so the bearer token is supplied as an environment variable and
substituted into the server headers at load time.

```powershell
$env:FABRIC_MCP_TOKEN = az account get-access-token `
  --resource https://api.fabric.microsoft.com `
  --query accessToken -o tsv
opencode
```

`opencode.json` reads it as `{env:FABRIC_MCP_TOKEN}`. Never put a literal token in that file.

**Known limitation:** Entra ID access tokens are short-lived (typically under 90 minutes). A long
session will eventually fail with 401. Refresh the variable and restart OpenCode. A token-refresh
wrapper is a release 2 candidate, not part of this adapter.

## Verify the installation

```powershell
opencode mcp list
```

Both servers should report `connected`:

| Server | Type | Notes |
| --- | --- | --- |
| `fabric-core` | remote | `https://api.fabric.microsoft.com/v1/mcp/core`, OAuth disabled, header token |
| `fabric-local` | local | `npx -y @microsoft/fabric-mcp@latest server start --mode all --namespace docs` |

Both are configured with `codemode: false` so each tool appears on the native tool list. That keeps
the generated permission rules easy to read and to audit. If you enable Code Mode, the same rules
still apply to the nested tools, but the tool list you see changes.

## The agent and the commands

| Name | Type | Purpose |
| --- | --- | --- |
| `fabric-deployer` | primary | Guides and verifies. Uses the full guardrail rule set. |
| `verifier` | subagent | Read-only environment verification. Cannot write or run shell. |
| `drift-checker` | subagent | Read-only declared-versus-live comparison. Cannot write or run shell. |
| `/provision-check` | command | Walks the provisioning checklist in dependency order |
| `/verify-env` | command | Read-only health check |
| `/drift-check` | command | Declared configuration versus tenant state |

Select the primary agent with `Tab`, or name it:

```powershell
opencode --agent fabric-deployer
```

## Guardrail ordering

OpenCode evaluates the `permissions` array top to bottom and **the last match wins**. The generated
array therefore runs broad first, specific last:

1. `shell` → ask
2. `fabric-core_*` → ask
3. each `fabric-core_delete_*` → deny
4. `fabric-local_*` → ask
5. each `fabric-local_docs_*` → allow
6. each read-only `fabric-core_*` tool → allow

If you hand-edit this array and put a read `allow` above the broad `ask`, reads will start prompting.
That is the ordering trap this generation step exists to avoid. Rebuild instead of editing.

The read-only subagents are stricter: they deny `*` first, then allow back only `read`, `glob`,
`grep`, `skill` and the read-only MCP tools.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `fabric-core` shows `needs authentication` | `oauth` is not disabled, or the header is missing | Confirm `"oauth": false` and the `Authorization` header in `opencode.json` |
| 401 mid-session | Token expired | Re-mint `FABRIC_MCP_TOKEN`, restart OpenCode |
| Every Fabric tool prompts | Rules not loaded | Confirm `opencode.json` is at the project root and contains `permissions` |
| `fabric-local` will not start | Node older than 22 | Install Node 22 LTS |
| `AGENTS.md` ignored | File not at project root | Copy it to the root, not into `.opencode/` |

## What this adapter cannot do

It cannot assign a workspace to a capacity, connect Git, create or bind connections, or configure
deployment pipelines. No official Fabric MCP tool exposes those operations. Those steps are in
`fabric/runbooks/` and are performed by a human in the Fabric portal. See the verification honesty
matrix in `AGENTS.md`.
